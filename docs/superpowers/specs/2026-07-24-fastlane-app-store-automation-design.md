# Fastlane App Store Automation — Design

**Date:** 2026-07-24
**App:** Tables (`com.challengr.Tables`, team `79242RQ384`)
**Goal:** Automate TestFlight builds, App Store screenshots, and metadata/binary
delivery for a small solo-developer iOS app with the least ongoing manual effort.

## Context

- iOS 26 universal app (`TARGETED_DEVICE_FAMILY = "1,2"`), version 1.0 / build 1.
- **Automatic** Xcode code signing; shared scheme `Tables.xcscheme` already exists.
- Existing `TablesUITests` target with accessibility identifiers on every screen
  (`home.countdown`, `home.progress`, `home.settings`, `setup.table.N`,
  `setup.start`, `game.problem`, `game.option.N`, `results.score`,
  `results.playAgain`, plus a "Your tables" progress screen).
- Tooling present: Ruby 3.3, Bundler 2.5, Xcode 26.6. Fastlane not yet installed.
- Repo: `github.com/col/Tables`. Apple Developer Program: **enrolled**, App Store
  Connect **app record already exists**.

## Decisions

| Area | Decision | Rationale |
|------|----------|-----------|
| Signing | **Keep Xcode Automatic signing; no `match`** | Single-Mac local workflow; `match` adds a certificates repo + manual signing for no benefit here. Deviates from the original "use match" request by explicit user choice; can be added later for CI/multi-Mac. |
| Auth | **App Store Connect API key** (`.p8` + Key ID + Issuer ID) | No Apple ID password or 2FA in automation; works for `gym`, `pilot`, and `deliver`. |
| Run location | **Local Mac only** | No CI secrets to manage for a small app. |
| Screenshots | **Full automated** via `snapshot` | User opted in; app already has identifiers to drive navigation. |
| Devices | **iPhone + iPad** (universal app) | Capture required iPhone 6.9" + 6.5" and iPad Pro 12.9"/13" sizes. |
| Release submission | **Upload only (`submit_for_review: false`)** | User makes the final Submit click in App Store Connect for the first release. |
| Languages | **en-US only** | Small single-locale app. |

## Components

### 1. Authentication (`app_store_connect_api_key`)
A single helper in the `Fastfile` loads the API key from `fastlane/`
(`.p8` file gitignored; Key ID and Issuer ID read from a gitignored
`fastlane/.env` so no secrets are committed). Every lane calls it and passes the
resulting key to `gym`/`pilot`/`deliver`.

### 2. Lane: `screenshots`
Runs `capture_screenshots` (snapshot) against `ScreenshotUITests` on the device
matrix in `Snapfile`. Output to `fastlane/screenshots/`. No signing / API key
needed (simulator only).

### 3. Lane: `beta`
1. `app_store_connect_api_key`
2. Set build number = `latest_testflight_build_number + 1` (via the API key).
3. `build_app` (gym) — scheme `Tables`, `export_method: app-store`,
   `-allowProvisioningUpdates`, automatic signing.
4. `upload_to_testflight` (pilot) — upload build; `skip_waiting_for_build_processing: true`.

Everyday "ship a build to TestFlight" command.

### 4. Lane: `release`
1. `app_store_connect_api_key`
2. Optionally run `screenshots` (or reuse existing output).
3. `build_app` (gym) as above.
4. `upload_to_app_store` (deliver) — uploads binary + `metadata/` + `screenshots/`,
   `submit_for_review: false`, `precheck_include_in_app_purchases: false`,
   `force: true` (skip the HTML preview prompt).

### 5. Screenshot UI test (`ScreenshotUITests.swift`)
Reuses existing identifiers. Launches the app with `setupSnapshot(app)` plus a
launch argument (reuse `-uiTesting`, which already caps the countdown so Game →
Results is fast). Captures, in order:

1. `01Home` — Home screen.
2. `02Setup` — after tapping `home.countdown`, on the Setup screen.
3. `03Game` — after selecting a table + `setup.start`, on `game.problem`.
4. `04Results` — after answering, on `results.score`.
5. `05Progress` — relaunch, tap `home.progress`, "Your tables" screen.

Each `snapshot("…")` call waits for the anchor element first
(`waitForExistence`) to stay deterministic across device speeds.

## Data Flow

```
developer ── fastlane beta ──▶ gym ──▶ .ipa ──▶ pilot ──▶ TestFlight
developer ── fastlane screenshots ──▶ snapshot ──▶ fastlane/screenshots/
developer ── fastlane release ──▶ gym + deliver ──▶ App Store Connect (draft, not submitted)
```

API key (`.p8` + IDs) is read locally and never committed.

## Error Handling

- Missing API key file / env vars → lane fails fast with a clear message pointing
  at the manual setup step.
- `gym` signing failures surface Xcode's automatic-signing error; `-allowProvisioningUpdates`
  lets Xcode create/download the distribution profile on demand.
- `snapshot` uses `waitForExistence` anchors so a slow simulator doesn't capture a
  blank/transition frame; a missing element fails the test with the identifier name.
- `deliver` runs `precheck` before upload to catch metadata rule violations early.

## Testing / Verification

- `bundle exec fastlane lanes` lists lanes without error.
- `bundle exec fastlane screenshots` produces PNGs for every device/screen combo.
- `bundle exec fastlane beta` (dry-run discussion first) uploads a build visible in
  TestFlight.
- Existing `TablesUITests` (`GameFlowUITests`) continue to pass — screenshot test is
  additive and must not break them.

## Manual Tasks for the User

1. **Generate App Store Connect API key**: App Store Connect → Users and Access →
   Integrations → App Store Connect API → generate a key with **App Manager** (or
   Admin) access. Download the `.p8` (one-time), note **Key ID** and **Issuer ID**.
   Place `.p8` in `fastlane/` and put the two IDs in `fastlane/.env` (both gitignored).
2. **Fill in metadata** in `fastlane/metadata/en-US/`: `description.txt`,
   `keywords.txt`, `name.txt`, `subtitle.txt`, `promotional_text.txt`, plus
   `support_url.txt`, `marketing_url.txt`, and a **privacy policy URL** (Apple
   requires one — set the app's privacy URL in App Store Connect if not already).
3. **Accept agreements**: ensure the free-app agreement (and, if paid, Paid Apps +
   tax/banking) is accepted in App Store Connect, or uploads are rejected.
4. Run the lanes and click **Submit for Review** in App Store Connect when ready.

## Out of Scope (YAGNI)

- `match` and any certificates repo.
- GitHub Actions / CI.
- Multiple localizations.
- Automated version-bump / changelog tooling beyond build-number increment.
